# Видео с личным HeyGen-аватаром

Локальный клиент лежит в `scripts/heygen-client.mjs` рядом с этим файлом. В начале работы
определи абсолютный каталог текущего скилла и используй его во всех командах:

```bash
# Codex
SKILL_DIR="$HOME/.agents/skills/heygen-avatar-oauth"

# Claude Code — вместо строки выше
SKILL_DIR="$HOME/.claude/skills/heygen-avatar-oauth"

node "$SKILL_DIR/scripts/heygen-client.mjs" doctor
```

Он сам удаляет `HEYGEN_API_KEY` из окружения, принимает только OAuth с
`billingType: subscription`, хранит незавершённый `video_id` и проверяет скачанный MP4.
Никогда не проси API-ключ и не копируй OAuth-файл с другого компьютера или сервера.

## Главный сценарий: живой голос пользователя

Если пользователь прикрепил голосовое или аудиофайл, в ролике должна звучать
именно эта запись. Не транскрибируй её для повторного синтеза и не заменяй голос
каталожным. Клиент принимает `ogg/opus`, `m4a/aac`, `wav`, `mp3` и видеофайл с голосом;
исходник не изменяется.

Выбор голоса из каталога — отдельная опция для будущих роликов из текста. Он никогда не подменяет
приложенную живую запись.

## Перед любым действием

Сначала запусти read-only диагностику:

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" doctor
```

Продолжай только при `ok: true`, `credentialType: oauth` и
`billingType: subscription`. При другой оплате остановись: предложи повторить OAuth-вход,
но не предлагай API-ключ.

Используй только аудио или видео, приложенное к текущей просьбе. Не угадывай старый файл
из другой задачи. Если абсолютный локальный путь вложения недоступен, попроси приложить
файл заново.

## Разрешение на расход кредитов

Одна недвусмысленная команда «сделай», «запусти», «сгенерируй» или «создай ролик»
разрешает ровно один рендер из указанного файла. Вопрос «можешь ли?» или просьба показать
аватары не разрешают расход.

Повторный вариант, смена аватара после запуска или новый `video create` требуют нового
явного запроса. Если HeyGen уже выдал `video_id`, сначала используй `resume`: повторная
загрузка статуса и скачивание не создают второй платный ролик.

## Стабильная личность и выбор образа

Конфиг хранит постоянную группу человека и отдельные проверенные образы для `9:16` и `16:9`.
Перед рендером клиент снова читает личный каталог: так удалённый или заменённый `look_id` не сломает
поток. Если внутри группы нет нужной ориентации, единственный готовый личный образ этого формата
можно выбрать автоматически; при нескольких кандидатах нужен выбор пользователя.

Если пользователь назвал другой образ или просит показать варианты, выполни:

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" avatars
```

Показывай только `lookName`, ориентацию и понятное имя группы. Не подставляй group id вместо
look id и не выбирай публичный стоковый аватар. Если вариантов несколько и нужный не указан,
задай один короткий вопрос.

Сохранить новый вариант по умолчанию можно без расхода кредитов:

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" configure \
  --look-id '<личный-look-id>' \
  --aspect '9:16'
```

Если пользователь не указал формат, используй сохранённый default; начальный default —
вертикальный `9:16`. Для YouTube по явной просьбе используй `16:9`.

## Создание аватара или нового образа

До вызова покажи пользователю итоговое описание внешности и дождись явного подтверждения.
Создание меняет кабинет HeyGen и может расходовать кредиты, поэтому флаг разрешен только после команды
«создай»:

```bash
# Из текстового описания
node "$SKILL_DIR/scripts/heygen-client.mjs" avatar-create \
  --type prompt --name '<имя>' --prompt '<утверждённое-описание>' \
  --aspect '9:16' --approve-credit-spend --set-default

# Из фотографии или видео для Digital Twin
node "$SKILL_DIR/scripts/heygen-client.mjs" avatar-create \
  --type photo --name '<имя>' --file '<абсолютный-путь-к-фото>' \
  --approve-credit-spend --set-default

node "$SKILL_DIR/scripts/heygen-client.mjs" avatar-create \
  --type digital_twin --name '<имя>' --file '<абсолютный-путь-к-видео>' \
  --approve-credit-spend --set-default
```

Для нового образа уже существующего человека добавь `--group-id '<постоянная-группа>'`. Не создавай новую
группу для смены одежды или фона. Клиент ждёт `status=completed`, превью и размеры кадра до 5 минут.
Фото принимаются в JPG, PNG или WebP, Digital Twin — в MP4, MOV или WebM. Максимальный размер
одного исходника — 32 МБ; неподходящий файл отклоняется до загрузки в HeyGen.

Если получен `requiresConsent: true`, создай ссылку только после согласия пользователя. Он сам записывает
согласие в браузере; не обходи этот шаг:

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" avatar-consent \
  --group-id '<group-id>' --approve-consent
```

После записи согласия повторяй `avatars`, пока образ не станет `completed`; затем сохрани его командой
`configure` для нужного формата. До готовности не запускай рендер.

## Выбор и прослушивание синтетического голоса

Сначала покажи три варианта с превью. Не выбирай за пользователя и не сохраняй голос, пока он его не выбрал.

```bash
# Готовые личные голоса
node "$SKILL_DIR/scripts/heygen-client.mjs" voices \
  --type private --language Russian --gender male --limit 20

# Три голоса по описанию
node "$SKILL_DIR/scripts/heygen-client.mjs" voice-design \
  --prompt '<тембр, энергия, акцент, Russian speaker>' \
  --locale ru-RU --gender male --seed 0

# Скачать выбранное превью и показать его как аудио
node "$SKILL_DIR/scripts/heygen-client.mjs" voice-preview \
  --voice-id '<voice-id>' --output '<абсолютный-путь.mp3>'

# Сохранить только после явного выбора
node "$SKILL_DIR/scripts/heygen-client.mjs" configure-voice \
  --voice-id '<voice-id>'
```

## Один рендер

Выбери абсолютный выходной путь заранее. Сохраняй результат в папке текущего проекта,
например `renders/heygen-avatar-v01.mp4`. Не перезаписывай существующий результат —
увеличь номер версии.

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" render \
  --audio '<абсолютный-путь-к-текущему-вложению>' \
  --aspect '9:16' \
  --output '<абсолютный-путь-к-новому-mp4>' \
  --approve-credit-spend
```

Добавляй `--look-id '<личный-look-id>'` только когда пользователь выбрал не default.
Флаг `--approve-credit-spend` допустим только после явного глагола действия из текущей
просьбы.

Команда может работать до 30 минут. Запускай её как длительный процесс и давай краткое
обновление не реже раза в минуту. Не запускай второй render, если ожидание прервалось.

## Продолжение существующего рендера

Используй сохранённый `video_id`:

```bash
node "$SKILL_DIR/scripts/heygen-client.mjs" resume \
  --video-id '<существующий-video-id>' \
  --output '<тот-же-абсолютный-путь-к-mp4>'
```

Ошибки различай по смыслу:

- `auth_or_network_unreadable` — потерян вход или связь, а не «ролик долго рендерится»;
- `video_timeout` — задача не закончилась за 30 минут, тот же id можно продолжить позже;
- `video_failed` — HeyGen завершил именно этот рендер ошибкой; новый не запускай сам;
- `video_status_unknown` — контракт изменился, остановись и проверь актуальную схему CLI;
- `audio_too_large` — попроси укоротить запись; новый video ещё не создан;
- `subscription_required` — OAuth не подтверждает подписочную оплату; ключ не предлагай.
- `matching_look_not_found` — нет однозначного готового образа нужной ориентации; покажи варианты;
- `avatar_not_ready_timeout` — новый аватар не успел подготовиться; не создавай дубль;
- `avatar_creation_failed` — HeyGen завершил создание ошибкой; покажи ошибку и не повторяй сам;
- `avatar_file_type_invalid` — нужен поддерживаемый формат фото или Digital Twin-видео;
- `avatar_file_too_large` — исходник больше 32 МБ; попроси подготовить меньший файл;
- `voice_preview_unavailable` — у голоса нет доступного превью; покажи другие варианты.

## Выдача результата

Клиент уже проверяет размер, длительность и декодирование MP4. Верни готовый файл по
абсолютному локальному пути в Codex, а не временную подписанную ссылку HeyGen. Укажи
использованный look и формат. Не пересказывай содержание записи без просьбы пользователя.
